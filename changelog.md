# BizUpKeep Astra Child - Changelog

## 1.33.0
- **A2Z's own revenue is now posted automatically** into its Internal Books company (see `InternalBooksPage`) whenever a real customer payment confirms for any of the four checkout flows (Registration, Annual Return, Amendment, Bookkeeping Monthly Subscription) - closes out the third and final round of the WooCommerce-catalog plan (round 1: Invoicing; round 2: the Service Catalog admin).
- Purely additive to the two existing `woocommerce_order_status_changed` handlers - no payment-confirmation or subscription-extension logic changed. Revenue posting is best-effort, sharing the same one-shot idempotency window as the existing confirmation (a new `_bizupkeep_a2z_revenue_posted` order-meta flag, separate from the existing confirmation flags): a failure here never blocks the actual payment confirmation, and staff can always capture a missed entry manually via Internal Books.
- Reads the resolved service's VAT treatment and display name straight off the `bizupkeep-core` Service Catalog (round 2) rather than re-deriving anything per order - only Bookkeeping Monthly's row is VAT-inclusive, so it's the only flow whose posted entry splits out a VAT Output line (and only when A2Z's own Internal Books company is itself VAT-registered).
- Silently does nothing if Internal Books hasn't been set up yet (`bizupkeep_bookkeeping_internal_company_uuid` option unset) - this is optional automation layered on an optional feature, never a blocker for a real customer's checkout.

## 1.32.0
- **New "Customers" and "Invoices" tabs on My Bookkeeping**, backed by the `bizupkeep-bookkeeping` 1.7.0 plugin's new Invoicing module - the biggest feature gap versus Sage/QuickBooks/Xero closed: a client can now invoice their own customers (not BizUpKeep's clients - a separate, external party who is never a WP user) and download a customer's statement of account.
- Invoices are created as an editable Draft (never posted), then **Sent** - which posts `Debit Accounts Receivable / Credit revenue category [/ Credit VAT Output]` via `LedgerServiceInterface` directly (a different economic-event shape than Capture's simplified 2-line posting) and emails a real PDF invoice to the customer. Recording a **Payment** posts `Debit Bank/Cash / Credit AR` to clear the receivable. A Sent/Paid invoice is immutable like any other journal entry - only a Draft can be **Voided**.
- Invoice line prices are VAT-inclusive, split backward the same way Capture/Recurring already do - one consistent VAT mental model across every capture path in this plugin.
- **Real PDF documents** (not print-styled HTML) via a new `dompdf/dompdf` dependency - the ecosystem's first true PDF-generation library. Customer emails are sent directly via `wp_mail()` with the PDF attached, bypassing BizHub's own `NotificationQueue` entirely - that system requires a recipient who is a real WP user and has no attachment support, neither of which fits a client's external customer.
- This round is scoped to manual payment collection only - no public "pay this invoice online" page yet, a deliberate choice to keep the first round self-contained (a public, unauthenticated payment surface is a separate, security-sensitive build of its own).
- Gated behind the same active-subscription check as Capture/Recurring for the paid actions (Send/Record Payment); viewing, creating drafts, and managing customers stays available to a lapsed client.

## 1.31.0
- **New "Recurring" tab on My Bookkeeping**, backed by the `bizupkeep-bookkeeping` 1.5.0 plugin's new Recurring module. A client defines a template once (type, amount, category, payment method, VAT flag, frequency - weekly/monthly/quarterly/annually - and a start date); a daily WP-Cron job generates a pending occurrence each time the template comes due, which the client must confirm (optionally editing the amount/date) or skip - occurrences never post themselves. A "Confirm All Selected As-Is" bulk action mirrors the Import tab's bulk-categorize convenience.
- Confirming an occurrence still delegates to `TransactionCaptureServiceInterface::captureIncome()`/`captureExpense()` - no new posting path, so the subscription gate, VAT support and balanced-entry guarantee are all inherited for free.
- A client is emailed once per company when new occurrences land in the review queue (not once per occurrence) - closes the risk that a review queue nobody is told about never gets reviewed.
- Templates can be paused, resumed, or deleted outright at any time (a template is a scheduling convenience, not an audit record, so unlike journal entries it needs no reversal ceremony).
- Gated behind the same active-subscription check as Capture/Import, since a recurring template is still automated capture.
- **Verified live end-to-end**: created a template with a past due date, fired the cron manually, confirmed a pending occurrence appeared and a real review-ready notification was queued/sent, confirmed it with an amount override and verified a real balanced journal entry posted with the Trial Balance still balanced, confirmed firing the cron again the same day never duplicates the occurrence, skipped a different occurrence and confirmed it never posted, paused a template and confirmed the cron stopped generating for it.

## 1.30.0

- **Verified live end-to-end**: staff-flagged a test company VAT-registered, confirmed the Capture tab's VAT checkbox appeared (and was absent for a non-flagged company), captured a VAT-inclusive income and expense transaction and confirmed the resulting journal entries had the correct 3-line split with the Trial Balance still balanced, confirmed the VAT Summary statement showed the correct Output/Input/Net figures, confirmed a non-VAT capture still posted its old 2-line entry unchanged.

## 1.29.0
- **New "Import" tab on My Bookkeeping**, backed by the `bizupkeep-bookkeeping` 1.3.0 plugin's new BankImport module: upload a bank statement CSV, map its columns (remembered per company for next month, both single-signed-amount and separate-debit/credit bank export styles supported), preview the parsed rows before committing, then review and categorize each staged transaction into a real journal entry - or bulk-categorize many at once, or ignore a row entirely (never posted). - The uploaded CSV is held in a short-lived WP transient between the upload and mapping steps (~15 min) - this theme has never written a file to disk for bookkeeping and doesn't start now for one temporary upload.
- **Verified live end-to-end** via real HTTP (multipart upload, not just curl-checked pages): a signed-amount-style statement and a separate debit/credit-style statement both parsed with the correct signs; re-uploading the identical signed-style statement produced zero new staged rows (`duplicates=3`); one row categorized posted a real balanced 2-line journal entry (Trial Balance still balanced afterward); one row bulk-categorized via the shared-category form; one row ignored and confirmed never posted; the whole tab correctly showed the subscription-locked message for a company with no active subscription.
